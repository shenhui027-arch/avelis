# M6 验收说明：问数表达能力

- 日期：2026-10-29
- 设计：[ADR 0005](decisions/0005-ask-expressiveness.md)
- 完成标准：在真实 StarRocks 上验证以下能力，以及它们与治理的结合（受影响拦截、权限）：
  - 排名与前 N；
  - 多个指标；
  - 环比 / 同比；
  - 派生指标。
- 测试：
  - 验收 [backend/tests/acceptance/test_m9_ask_v2.py](../backend/tests/acceptance/test_m9_ask_v2.py)，8 项，含真实 DeepSeek 1 项；
  - 单元测试 [backend/tests/unit/test_ask_v2.py](../backend/tests/unit/test_ask_v2.py)，4 项。

## 演示数据

| 日期 | 区域 | 实付销售额 | 订单数 |
|---|---|---|---|
| 2026-09-14 | 华东 | 90 | 1 |
| 2026-09-15 | 华东 | 300 | 2 |
| 2026-09-15 | 华北 | 150 | 1 |
| 2026-09-15 | 华南 | 60 | 1 |
| 2026-09-16 | 华东 | 80 | 1 |

派生指标“客单价”= `paid_sales / orders_cnt`。

## 场景与实际行为

| # | 问题 | 断言的实际行为 |
|---|---|---|
| 00 | 创建并发布派生指标“客单价” | 公式含非白名单语法时 422；共有维度自动为“区域”；提交时锁定两个组成版本；负责人不能自审；复核者批准后发布 |
| 01 | 2026-09-15 各区域实付销售额前 2 | 华东 300、华北 150；单指标排名下推到 SQL（`ORDER BY … DESC LIMIT 2`） |
| 02 | 2026-09-15 各区域实付销售额和订单数 | 列为“区域、实付销售额、订单数”，3 个区域对齐；2 个子查询、2 条 SQL；版本为两个指标各自的已发布版本 |
| 03 | 2026-09-16 华东区实付销售额 环比 / 同比 | 环比：80、上一期 300、变化 −220、变化率 −0.7333，上一期区间为 2026-09-15。同比：去年同期没有数据，如实为空，不当作 0 |
| 04 | 2026-09-15 华东区客单价；各区域客单价前 3 | 150，答案引用客单价与两个组成版本，依据给出公式；排名为 150、150、60（华南） |
| 05 | 实付销售额的视图被改为净额并采集 | 实付销售额受影响，客单价**级联受影响**。问客单价被拦截，问“订单数和实付销售额”也被拦截，消息指明是实付销售额；单问订单数照常。改回原定义、两个复核任务分别“已恢复”后，客单价恢复为 150 |
| 06 | 只属交易域的用户问“实付销售额和类目销售额” | 类目销售额的来源含商品域，整个答案被拒绝，没有返回任何部分结果 |
| 07 | 真实模型：“2026年9月15日各区域的实付销售额和订单数分别是多少？按实付销售额从高到低排” | 模型给出 `metric_codes=[paid_sales, orders_cnt]`、`order=desc`；后端排序得到华东 300、华北 150、华南 60；解释为模板（不外发结果） |

## 尚未验证

- 子查询结果超过行数上限时的排名提示（只有单元级逻辑，演示数据量触发不到）。
- 派生指标的组成指标跨数据源（例如 StarRocks 与 PostgreSQL 各一个）：机制相同，未单独验收。
