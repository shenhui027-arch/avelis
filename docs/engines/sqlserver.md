# SQL Server 默认跟踪与 DDL 归因

元数据、视图血缘、问数与执行前核对的实机核验见 [ADR 0004](../decisions/0004-engine-adapters.md)。DDL 归因已在 SQL Server 2022 Developer 上实机验证（2026-11-02）。

## 前提

- 默认跟踪已启用（`default trace enabled = 1`，SQL Server 默认开启）。
- 采集账号具有 `ALTER TRACE` 权限；部分环境读取跟踪还需要 `VIEW SERVER STATE`。
- 无需绑定审计表。

## 归因规则

- 只采用表、视图的**已提交**对象事件（Created / Altered / Deleted 的 Commit 阶段）；在事务中执行后回滚的 DDL 不会产生事件。
- 数据库名与配置的模式名由服务器按自身 collation 比较，大小写不敏感的实例上配置大小写与目录不一致也能匹配。
- 默认跟踪不记录模式名。模式只能从当前目录按对象 ID 恢复为候选，不能证明事件发生时对象属于该模式；已删除或改名的对象不猜模式。因此这些事件只作为不确定候选，归因结果为“可能”而不是“确定”。
- 默认跟踪没有语句原文，列级变化无法点名到具体列。

## 写盘延迟

默认跟踪是异步写盘的：实机上 DDL 后约 2 秒内读取可能还没有记录，约 6 秒后稳定出现。采集完成后，Avelis 会在读取默认跟踪前等待，直到距本次快照开始满 10 秒（最多等待 10 秒），再给出归因结果。10 秒是在观测值之上留的余量，不是 SQL Server 的写盘承诺；极端情况下仍可能漏读刚发生的 DDL，此时显示为“未找到审计记录”。

## 时间

`StartTime` 是服务器本地时间，按服务器当前的 UTC 偏移换算为 UTC。演示实例偏移为 0，非 UTC 时区与跨夏令时的换算未经实机验证；跨夏令时切换前后的事件时间可能偏差一小时。
