# ADR 0002：后端基础选型与治理模型落地

- 状态：已采纳
- 日期：2026-10-29

## 背景

M1 要在真实 StarRocks 上跑通“采集 → 血缘 → 口径 → 变更 → 复核 → 受约束问数”的闭环。约束如下：
- 元数据库要同时兼容 PostgreSQL 与 MySQL。
- 前后端分离。
- 凭据不能进入日志或模型上下文。
- 认证使用成熟开源实现，不自己造轮子。

## 决定

1. **认证用 FastAPI 官方安全模式 + 成熟库**，不自写密码学：
   - 登录：OAuth2 密码模式（`OAuth2PasswordBearer` / `OAuth2PasswordRequestForm`）。
   - 口令哈希：pwdlib 0.3.1（Argon2）。
   - 访问令牌：PyJWT 2.15.1（HS256），令牌带 `jti`，注销时写入 Redis 吊销。
   - 数据源口令：cryptography 的 Fernet（MultiFernet，可轮换密钥）加密存储，密钥由 `AVELIS_SECRET` 经 HKDF 派生。

   **未采用 fastapi-users**，原因有三：
   - 15.x 已进入维护模式，不再加新功能。
   - 它的数据库适配只支持异步 SQLAlchemy，与本项目的同步数据层不一致。
   - 它依赖 `redis<8`，与已固定的 redis 8.1.0 冲突。

   我们采用的 pwdlib、PyJWT 正是 fastapi-users 自身依赖的底层库。
2. **数据层：同步 SQLAlchemy 2.1 + Alembic，一套迁移同时跑 PostgreSQL 18 与 MySQL 8.4。**
   - 主键由应用生成（32 位十六进制）。
   - JSON 用通用类型。
   - 时间统一存不带时区的 UTC，MySQL 用 `DATETIME(6)`。
   - 状态存短字符串。
   - 不依赖 `RETURNING`、数组、部分索引。
   - 降级只删表。原因是 MySQL 的 DDL 不在事务内，且不允许先删外键正在使用的索引。
3. **任务队列自建在 job 表上，Redis 只负责唤醒**，不引入 arq：
   - 事实来源是 job 表。
   - Redis 丢失时，worker 定期扫描排队过久的任务，任务不会丢。
   - 同一数据源的采集用 Redis 锁互斥。
   - 定时采集由 worker 按数据源间隔入队。

   这样少一个依赖，语义也更直接；任务类型增多后再评估 arq 或其他队列库。
4. **资产身份与名称分离**：
   - 内表用 `TABLE_ID` 判定身份：改名可确认，同名重建算新资产。
   - 视图、外部表、Catalog 表没有物理 ID，按“Catalog + 库 + 名 + 类型”匹配。改名只记为候选（定义指纹相同），不自动合并。
   - 字段消失后再出现，分配新的字段 ID。
5. **字段推导指纹是治理的锚点**。指纹的组成：
   - 实体表字段：字段 ID + 类型。
   - 外部表字段：再加上经身份映射追到的他库字段指纹。
   - 视图字段：再加上本列表达式、取值来源指纹、全部影响条件（过滤 / 关联 / 分组）及其来源指纹。

   以下对象都绑定指纹：
   - 人工确认；
   - 指标版本：提交时记录每个依赖字段的指纹；
   - 关联路径；
   - 声明的粒度。

   效果：
   - 只改格式不变。
   - 改表达式、过滤、关联，或上游字段被删除、重建，都会变。
   - 未解析、来源未采集时状态为 `unknown`，按受影响处理。
6. **两条状态线**：
   - 观察到的事实：资产版本、指纹。
   - 业务批准：指标版本状态。

   问数要求两者同时满足。版本状态为 `published`，且依赖指纹与提交时一致，才会执行。后果：
   - 定义变化后，即使尚未复核，也立即拦截。
   - 定义恢复后，也要负责人复核确认才放行。
7. **问数：模型只出意图，SQL 确定性编译。** 执行前对实际 SQL 重新解析语法树做校验：
   - 单条 SELECT，没有禁止的节点；
   - 只引用批准的表和已采集的列；
   - 有 LIMIT 上限。

   执行条件：
   - 使用只读账号；
   - 会话设置 `query_timeout` 与 `query_mem_limit`；
   - 错误 5024 如实返回为“查询超时”。

   权限沿血缘与身份映射找全部来源（视图是 `SECURITY NONE`，授予视图等于暴露其来源），每个来源都要可见。
8. **粒度**：
   - 存储的粒度有三种来源：数据库主键 / 唯一键（observed）、GROUP BY / DISTINCT（parsed）、人工声明（declared，可用只读查询核验）。
   - 推导的粒度有两种：外部表经身份映射继承（linked）、单表视图透传（passthrough）。
   - 关联基数由“关联列是否覆盖右侧粒度”推出。可加度量（SUM / COUNT / AVG）经 1:N 或 N:N 关联后聚合时，阻止发布，并提示先聚合再关联。

## 后果

- 每次采集后重算全部指纹。v0.1 资产量小，没有问题；规模变大后要改为只沿受影响的闭包增量计算。
- 未归属业务域的资产不做域限制（v0.1）。生产使用前应让所有资产都有归属，或改为默认拒绝。
- 问数意图目前只有演示适配器（规则匹配）。Anthropic / OpenAI 兼容适配器在 M2 接入；拿到 key 前，真实模型端到端标“未验证”。
- 接口的响应体暂未全部声明为 Pydantic 模型。M3 生成前端类型前补齐。
