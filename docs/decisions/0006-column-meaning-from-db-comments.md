# ADR 0006：字段含义以数据库列注释为准

- 状态：已采纳
- 日期：2026-10-29

## 背景

M6 走查时，问数结果表的维度列表头显示内部名 `region`。最初的修法是由后端附上维度的显示名（`labels`），表头改为“区域”。

这个做法的问题在于把字段含义的维护放到了 Avelis。数据库里的列注释（COMMENT）是团队已有的、和表结构一起变更的元数据。如果 Avelis 另起一套显示名：

- 两边会逐渐不一致；
- 注释缺失会被显示名掩盖，数据库侧没有动力补齐。

数据治理应保证数据库里的注释有解释，Avelis 负责把缺口暴露出来。

## 决定

1. **原样展示列名，附数据库注释。** 问数结果的维度列、资产字段列表都显示原始列名（例如 `region`），列名下方显示注释。结果中不再返回 `labels`，改为 `column_docs`。
2. **注释状态**（`governance/column_docs.py`）：

   | 状态 | 含义 | 是否计为缺口 |
   |---|---|---|
   | `ok` | 本列有注释；与列名相同的注释视为没有 | 否 |
   | `linked` | 外部表 / Catalog 表：经身份映射取源表同名列的注释，含义在源库维护 | 否 |
   | `inherited` | 视图列没有注释，但直接取值的唯一上游列有，建议在视图上沿用 | 是 |
   | `missing` | 本列与上游都没有注释 | 是 |

   沿用只限“直接取值（`value_direct`）且只有一个上游列”的情况；聚合、表达式列不推断含义。
3. **暴露缺口，推动数据库侧补齐：**
   - 问数表头、资产字段：缺口显示“缺注释（上游：…）”或“注释缺失”。
   - 数据源详情：按数据源统计注释完整度（`ok + linked` / 总列数），列出缺注释的列及可沿用的上游注释，可导出 CSV 交给数据库负责人。接口为 `GET /api/metadata/comment-gaps?datasource_id=`，只包含当前用户可见的资产。
   - 发布检查：口径依赖的列缺注释时给出提示；`AVELIS_REQUIRE_COLUMN_COMMENTS=true` 时改为阻断发布（默认关闭，逐步收紧）。
4. **数据库补注释后自动生效。** 列注释参与资产内容哈希，注释变化在下次采集时生成新版本。注释不进入字段推导指纹，所以不会让口径受影响。

## 后果

- Avelis 不维护字段显示名。口径的维度 `label` 仍是口径定义的一部分，用于说明口径，不替代列注释。
- 推断“可沿用的上游注释”只看最近一次采集的列级血缘；血缘为未知或断开时不推断，按缺失处理。
- 缺口清单为只读视图，不回写数据库：注释由数据库负责人在源库修改。
