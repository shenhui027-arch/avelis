# ADR 0020：图表规格由后端确定性选图，前端用 ECharts 渲染，模型通过工具表达偏好

- 状态：已采纳（2026-11-03）。已实现：第 1 阶段选图器与图表规格（PR #96），第 2 阶段问数出图与 `chart` 工具（PR #97），第 3 阶段分析报告插图与导出复用规格（PR #98），合并后的评审修复（PR #99：多指标分图、面板上限 8、导出比率之差按百分点）。
- 发布版本：第 1–3 阶段 v1.0.3（v1.0.2 及更早版本不包含）；第 4 阶段（用对话改图与图上标注，PR #110）v1.0.4。
- 相关：ADR 0009（量纲与引用）、0010（产品与业务解耦）、0013（准确来自受治理的元数据）、0014（列契约：角色、量纲、期望方向）

## 背景

2026-11-03 的审计发现：问数回答一张图都不出，只有表格；分析页只有两种手写 SVG 图，而且放在默认收起的证据栏里；PDF / HTML 导出又用另一套 Python 规则选图，两套规则已经出现差异；模型不参与选图，用户也没法说“画成饼图”。数值也没有按量纲显示，比率会显示成 13 位小数。

后端其实已经给出了选图需要的元数据（ADR 0014 的列契约：角色、量纲、期望方向，以及意图里的时间粒度、分组、排序、对比期），只是没人用。

## 决定

### 1. 选图只在后端做一次，产出已物化的图表规格

- `avelis/charts.py::recommend(columns, rows, roles, units, polarity, intent, preference=None)` 只依据列契约与意图选图，不看列名、不猜业务。
- 返回 `charts` 列表：第一个为默认图，其余为同一份数据可切换的候选。每个规格都是**已物化**的：排序、截断（类目最多 20、时间×维度最多 8 个系列）、合并“其他”、透视、缺格补空都在后端完成。渲染端（页面、导出）只画，不再推断。
- 规则要点：单行无维度为指标卡；时间序列为折线；时间×维度为多折线；维度为排好序的横向条形；维度 + 对比期为变化发散条；不同量纲的多个度量为分图。**不使用双纵轴**（两个刻度可以任意对齐，容易误读）。比率、变化率等不可相加的量不堆叠、不画环形、不合并“其他”。
- 问数答案与分析数据集在**读取时**计算规格，不写库。规则改进后旧答案也能受益；数据集按全部已保存行计算，不受分页影响。

### 2. 模型通过 `chart` 工具表达偏好，由选图器校验

- 问数的解释步骤给模型注册 `chart` 工具，参数为 `kind`、`title`（一句结论式标题）、`top_n`。发给模型的可选图只有当前数据合法的那几种；不在其中的选择被忽略。
- 模型的选择存为答案证据 `evidence.chart`，读取时作为 `preference` 传给选图器：匹配的图置顶、带上标题，`top_n` 只对排名类条形生效。
- 模型不能生成任意图表配置：配置不可校验、容易出错，也有注入风险。没有模型、模型不支持工具调用，或者不允许发送查询结果时，沿用规则默认图。

### 3. 数值显示与后端同一套规则

前端 `numbers.ts` 移植 `grounding.display`：比率显示为百分比；从 1 万起按万 / 亿（或 K / M / B）缩写；带口径单位；差额与变化率带符号。表格、坐标轴、提示框、指标卡都用它。

### 4. 图表库：ECharts 6（按需引入、懒加载）

| | ECharts 6.1.0（采用） | Recharts | Observable Plot | 继续手写 SVG |
|---|---|---|---|---|
| 许可证 | Apache-2.0 | MIT | ISC | — |
| 需要的图形 | 齐全（缩放、环形、分图、发散条） | 缺缩放，瀑布要自己拼 | 交互要自己补 | 每种都要自己写 |
| 体积 | 按需引入后单独分块，gzip 约 200 KB，首次出图时才加载 | 约 100 KB | 约 60–90 KB | 0 |

- 只引入折线、柱、饼三种图和网格、图例、提示框、缩放、标题组件，用 Canvas 渲染（导出 PNG 直接可用）。
- 主题从设计令牌读取（新增 `viz-1…8` 分类色与中性、网格、坐标轴色），深浅两套各自用色盲校验脚本验证。浅色下有 3 色对比度低于 3:1，补救办法是始终提供表格视图，单系列条形带数值标注。
- 系列颜色按固定顺序分配，不按排名；“其他”用中性色；变化条只在期望方向已知时用好 / 坏色，未知时中性。

### 5. 导出

PDF / HTML 导出继续用 reportlab 绘制（部署自包含，导出文件不依赖外部资源），改为读取同一份规格，不再保留独立的选图规则。Markdown 导出对折线与条形输出 Mermaid `xychart-beta`，其他图退回表格。

## 后果

- 选图规则只有一处，可单测；页面与导出的图类型一致，线宽、字体等细节允许有差别。
- 每增加一种图，后端选图器、前端配置生成、导出渲染都要改。
- 图的质量依赖口径元数据：没有填期望方向的口径，变化不着色；量纲未知时数值按“未知”显示。

## 第 4 阶段：用对话改图（v1.0.4）

图表偏好继续以 `charts.ChartPreference` 为唯一契约。分析与问数的 `chart` 工具从同一契约派生参数和说明；模型只表达展示偏好，不生成渲染配置。新增三个可选参数：

- `sort`：`value_desc`、`value_asc`、`category`，分别按首个所选系列的值降序、升序、类目显示值的自然顺序排序，在截断和合并“其他”之前生效。时间轴始终保持时间顺序，严格工具拒绝 `sort` 并说明原因。
- `marks`：`max`、`min`、`average` 的子集，对最终所示的每个系列计算。极值相同时标出所示顺序中的首个点；空值不参与计算。平均值是**所示非空值的算术平均**，包含合并后的“其他”；比率也允许平均标注，但它不是整体比率或加权平均。
- `highlight`：最多五个类目显示名，精确匹配最终显示的完整类目名，其余类目弱化。多维类目使用规格中的完整组合显示名；被 Top N 排除的类目不可高亮，工具返回当前可选项。

上述参数可与 `kind`、`title`、`top_n`、`measures` 组合；`top_n` 保持既有适用范围。无效偏好在通用选图器读取时整体忽略，严格分析工具则报错并列出可用图种、度量或类目，避免只应用一部分要求。

规格增加可空的 `marks`、`highlight`。`marks` 是 `{type, series, series_index, x, value}` 数组：`series` 为稳定列名，`series_index` 是当前规格 `series` 的从零开始的下标，用于区分时间与维度透视后共用列名的多个系列；极值的 `x` 为规格中实际显示的类目或时间值，平均线的 `x` 为 `null`；`value` 保持原始量纲。`highlight` 保存要突出的类目显示名。渲染端只消费这些字段，不再计算极值、平均值或决定图种。

分析续问的理解阶段新增 `question_type: "chart"`：仅修改上一轮结果的图种、排序、Top N、标注、高亮、所选度量或标题时进入 `chart_edit`；需要新时间范围、新筛选、新分组或新口径时仍走取数或分析。续问上下文保存上一轮实际插图的目录和本轮可读数据副本；取数快路径没有分析数据集时，将已保存答案结果复制成受治理数据集。复制保留原始列、完整行、锁定版本与来源，不执行数据源查询，也不修改上一轮数据。

`chart_edit` 只绑定从偏好契约派生的 `chart` 工具，向模型提供用户原话、列显示名、角色、量纲、当前图种和偏好，以及数据支持的图种、度量和类目。仅调用一次改图模型，再交由选图器严格校验。有多张图时必须有用户明确的选择依据；无法定位就沿用已有澄清流程，不能默认选择首图。模型要求非法图种或不存在的类目时，本轮明确说明原因和可选项，不保存伪造的图。

成功报告为 `kind: "chart"`，保存 `dataset`、完整的生效 `preference`，以及同偏好的 `figures` 记录。报告说明使用系统固定文案，不手写数据数字；运行详情、数据集详情和报告导出都在读取时用同一偏好物化完整规格，不受分页影响。改图前、模型返回后和读取时仍核对数据来源权限；撤权后既不能继续改图，也不能从规格、高亮名称或偏好中读取受限信息。

PDF 与 HTML 沿用同一 reportlab 图形：极值点加标记，笛卡尔图的平均值画虚线，高亮之外的类目使用浅色；环形图的平均标注用图下文字表达。Markdown 在图下列出标注值、高亮类目和平均值的含义。前端由规格消费者实现显示，本阶段不增加前端选图分支；定时任务流程不变。

没有采用重新执行问数或让模型输出 ECharts 配置：前者会改变数据快照并增加查询，后者无法复用确定性校验和各导出格式。测试以假模型验证独立路由与零数据源查询，并在真实 PostgreSQL 上验证续问复制、规格读取与权限撤回。
