# ADR 0019：MCP 服务，向外部 AI 工具提供受治理的口径与血缘

- 状态：部分采纳（2026-11-02）。形态、首批工具、审计已确定；鉴权由用户定为 Avelis 内置 OAuth 2.1 授权服务器。排在 1.1 第二项（在 ADR 0017 §3 口径语义提示之后）。具体库的接法在实施前的设计评审中定稿。
- 相关：ADR 0002（后端基础与选型原则）、0005（问数表达力）、0008（审计）、0013（准确来自受治理的元数据）、0017（口径语义提示）、0018（治理事件）；参考 Apache Gravitino `mcp-server/`（独立的 Python 服务，工具按对象分组，每次调用记审计）

## 背景

越来越多的人在 Claude、Cursor、ChatGPT 这类工具里直接问数据问题。这些工具自己写 SQL，不知道企业的口径、关联路径和血缘，答案常常“看起来对”。Avelis 已经有受治理的口径、编译器和血缘，但只能通过 Avelis 自己的页面使用。

MCP（Model Context Protocol）是这类工具接入外部能力的通用协议。Gravitino 用一个独立的 Python 服务，把元数据操作暴露成 MCP 工具，并对每次调用记审计、从认证信息解析调用人。

2026-11-02 调研的规范现状：

- MCP 当前规范为 `2026-07-28`：协议改为无状态，去掉了 initialize 握手与 `Mcp-Session-Id`，协议版本和客户端能力随每个请求的 `_meta` 传递，Streamable HTTP 服务可以直接放在负载均衡后面。
- 鉴权在规范里是可选的；一旦对 HTTP 传输做鉴权，MCP 服务就是 OAuth 2.1 资源服务器：必须提供 RFC 9728 受保护资源元数据，未认证请求返回 401 并在 `WWW-Authenticate` 里指向该元数据；必须校验令牌是签发给本服务的（RFC 8707 资源指示），不接受其他来源的令牌。客户端注册推荐 Client ID Metadata Documents（CIMD），动态注册（RFC 7591）已标为弃用但仍兼容。
- 只走 OAuth 流程的客户端（例如网页版的远程连接器）无法使用静态的个人访问令牌，因此原草稿的“个人访问令牌”方案被替换。

## 决定

### 1. 形态

- 作为后端的一个可选模块，挂在 `/mcp`，使用 Streamable HTTP 传输，按 `2026-07-28` 规范无状态运行。同一个镜像，配置开关默认关闭。
- 所有工具按令牌所代表用户的业务域权限执行，**和他在页面上能看到、能做的完全一致**。

### 2. 鉴权：Avelis 内置 OAuth 2.1 授权服务器

- Avelis 同时承担授权服务器和资源服务器两个角色：
  - **授权服务器**：授权码 + PKCE（只允许 `S256`）；RFC 8414 授权服务器元数据；授权响应带 `iss`（RFC 9207）；令牌请求必须带 `resource`（RFC 8707），签发的令牌绑定到 `/mcp` 的规范 URI；令牌吊销（RFC 7009）。
  - **资源服务器**：`/mcp` 提供 RFC 9728 受保护资源元数据，只接受本授权服务器签发、且受众为本服务的令牌。
- **用户授权复用现有登录**：授权页使用 Avelis 自己的登录会话，展示客户端名称、请求的权限范围和可访问的业务域，由用户确认。不新增账号体系。
- **客户端注册**：支持 CIMD（以 HTTPS URL 作为 `client_id`，获取客户端元数据时防 SSRF：只允许 https、限制大小与超时、可配置禁止内网地址），并兼容 RFC 7591 动态注册以支持旧客户端；管理员可在页面上查看和吊销已授权的客户端。
- **令牌**：访问令牌短期有效，刷新令牌可吊销；只存哈希，不落明文。权限范围先定为 `metrics:read`、`lineage:read`、`ask:execute` 三项，按最小权限申请。
- **选型（遵循 ADR 0002，不手写协议与加密）**：
  - 资源服务器一侧用官方 MCP Python SDK（2026-11-02 时 `mcp` 2.3.0，支持 `2026-07-28`）的 `TokenVerifier` 与受保护资源元数据；SDK 内嵌授权服务器的 `auth_server_provider=` 官方不建议新项目使用，不采用。
  - 授权服务器一侧用 Authlib（2026-11-02 时 1.9.2，Apache 许可的成熟库，已实现 RFC 6749 / 7636 / 7009 / 7591 / 8414 / 9207 / 9728 等）。它的授权服务器集成只有 Flask / Django，需要为 FastAPI 写一层请求 / 响应适配；RFC 8707 资源绑定与 CIMD 需要在其扩展点上补齐。
  - 实施前做一次小型技术验证（授权码 + PKCE + 资源绑定 + CIMD 跑通一个真实 MCP 客户端），再锁定具体版本，写入依赖与本 ADR。

### 3. 首批工具：只读 + 受治理的问数

| 工具 | 作用 | 所需权限 |
| --- | --- | --- |
| `search_metrics` | 按关键词、同义词、业务域检索已发布口径，返回名称、说明、维度、`ai_context`（ADR 0017） | `metrics:read` |
| `get_metric` | 一个口径的完整定义：表达式、时间语义、单位、可用维度、依赖资产 | `metrics:read` |
| `ask_metric` | 结构化问数：口径 + 维度 + 时间范围 + 过滤。由 Avelis 编译和执行，返回数字和依据（口径版本、SQL、数据时间） | `ask:execute` |
| `lineage_neighbors` | 一个资产或列的上下游 | `lineage:read` |
| `list_changes` | 某资产或口径近期的结构变化和影响 | `lineage:read` |

- **调用方不能传 SQL。** `ask_metric` 只接受结构化意图，和页面问数走同一个编译器。模型永远不直接写查询，这一点和现在一致。
- 口径状态不是 `published`（例如 `affected`）时拒绝查询，并说明原因，和页面行为一致。
- 结果行数和超时沿用问数的限制。数据发往外部模型的开关（数据外发设置）同样生效：关闭时只返回口径定义，不返回数据行。

### 4. 审计

每次工具调用写一条审计：`action = mcp.<工具名>`，记录调用人、客户端 ID、令牌 ID（不是令牌本身）、参数摘要，不记录返回的数据行。授权、吊销、客户端注册也写审计。

### 5. 写操作暂不开放

创建或修改口径、批准关联路径、导入血缘都不提供。以后如果开放，只能生成草稿或候选，走现有审核，并在工具元数据里标明是写操作。

## 不做

- 不提供执行任意 SQL 的工具，包括只读 SQL。
- 不做独立部署的 MCP 进程，避免出现第二套权限实现。
- 不支持匿名访问；不接受外部签发的令牌（对接企业 IdP 以后另议）。
- 不实现 MCP 已弃用的能力（Roots、Sampling、Logging）和旧的 HTTP+SSE 传输。

## 后果

- 好处：外部 AI 工具可以直接用上受治理的口径，答案有依据、可追溯；按规范实现 OAuth 后，只走 OAuth 流程的客户端也能接入。
- 代价：新增授权服务器（客户端、授权码、令牌三类数据和一次迁移）、授权确认页面、客户端管理页面，以及 MCP SDK、Authlib 两个依赖和一层 FastAPI 适配。
- 风险：令牌泄露等同于账号部分能力泄露。对策：访问令牌短期、权限范围最小化、按业务域限权、可随时吊销，异常调用量进入 ADR 0018 的告警事件；CIMD 拉取客户端元数据有 SSRF 风险，按 §2 限制。

## 待讨论

1. 令牌能否在用户自身权限之内进一步缩小到部分业务域（授权页勾选）？
2. `ask_metric` 返回的数据行数上限是否要比页面更低？
3. 是否同时提供 `ask_analysis`（多步分析）？它耗时长、成本高，可能需要异步和配额。
