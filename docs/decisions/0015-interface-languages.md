# ADR 0015：界面多语言（简体中文、繁体中文、英文）

- 状态：已采纳
- 日期：2026-11-01

## 背景

Avelis 的界面文案、后端错误提示、报告导出里的固定标签都是写死的简体中文，散落在组件和接口里。要面向繁体中文和英文用户，需要：

- 界面文案集中管理，三种语言齐全；
- 日期、数字、大数单位（万 / 亿 与 K / M / B）、相对时间按语言格式化；
- 后端给用户看的固定提示按请求语言返回；
- 用户与模型产出的内容（报告正文、经验、元数据注释、指标名）原样显示，不翻译。

## 决定

### 前端

1. **选型：i18next + react-i18next + i18next-browser-languagedetector。**
   - React 生态里使用最广、维护活跃，支持插值、复数、回退语言、TypeScript 键类型检查；
   - 对比 FormatJS（react-intl）：FormatJS 的 ICU 消息格式更强，但需要编译期抽取或运行时解析，本项目的文案以短标签为主，复数只在英文少量出现，i18next 的 `_one / _other` 足够；
   - 日期、数字、相对时间直接用浏览器内置的 `Intl`（`DateTimeFormat`、`NumberFormat` 的 compact 记数法、`RelativeTimeFormat`），不另引入格式化库。
2. **语言与默认值。** 支持 `zh-CN`（默认）、`zh-TW`、`en`。选择存在本机浏览器（`localStorage` 的 `avelis.lang`）；没选过时按浏览器语言：`zh-TW / zh-HK / zh-MO / zh-Hant` 用繁体，其他 `zh*` 用简体，`en*` 用英文，其余用简体。自动检测的结果不写入本机，浏览器语言变了还会跟着变。
3. **语言包。** `frontend/src/i18n/locales/{zh-CN,zh-TW,en}.json`，按页面分组的语义键（如 `login.submit`、`status.published`）。键以简体包为准，`i18next.d.ts` 让 tsc 检查键名与插值参数。繁体包先用 OpenCC（s2twp，台湾正体与常用词）从简体生成，再人工校对产品术语（資料來源、欄位、設定、帳號、登入等）。
4. **取词方式。** 组件与工具函数统一用 `i18n` 模块导出的 `t()`；枚举值（状态、对象类型、角色）用 `labelTable()` 生成取值时才翻译的标签表。切换语言时整棵界面按语言重新挂载（`LanguageRoot`），模块级标签和工具函数都会取到新语言，查询缓存保留。语言切换很少发生，重新挂载丢掉未提交的表单输入可以接受。
5. **入口。** 用户菜单里与主题并列的“语言”分组；登录页右上角的语言下拉。
6. **格式化。** `format.ts` 的时间函数跟随语言：中文保持 `2026-11-01 14:30`，英文 `Nov 1, 2026, 14:30`；只要时刻、只要日期、分组用的日期键各有单独的函数，不再对格式化结果做字符串截取。大数用 `Intl.NumberFormat` 的 compact：简体 万 / 亿，繁体 萬 / 億，英文 K / M / B。时区始终是业务时区。
7. **检查。** `pnpm check:i18n`（`scripts/check-i18n.mjs`）：三种语言键一致（复数后缀归到同一个键）、无空值、插值参数一致、英文包无中文、繁体包无常见简体字、源码里的静态键都存在，以及业务中立词扫描（繁体与英文的行业词；简体词由后端 `test_business_neutral.py` 覆盖，见 ADR 0010）。

### 后端

8. **请求语言。** 前端每个请求都带 `Accept-Language: <界面语言>`；后端用 Babel 协商成三种之一，放在请求上下文里。语言偏好只存在前端本机，不加用户表字段。
9. **消息目录。** gettext `.po`，msgid 是现有的简体原文（带 `{name}` 占位的模板），运行时用 Babel 读取。常量消息按原文查目录；拼接出来的消息改成 `Msg(模板, **参数)`，它本身就是格式化好的简体字符串（日志、`str(exc)`、已有断言不变），出口处再按请求语言翻译模板。参数值（名字、SQL 报错原文）不翻译。
10. **出口。** 治理层错误、`HTTPException`、连接器与锁等错误处理器在返回前翻译 `detail`；报告导出里的固定标题与标签按请求语言输出，报告正文原样。

### 分析智能体与问数

11. **系统提示与工具说明保持一份**，核验与引用规则不因语言改变。回答语言默认跟随界面语言（配置 `reply_language = "auto"`，可固定为某一种）。语言指令放在每次运行的用户消息里，不放进系统提示，保证前缀缓存仍能命中。指令要求指标名、维度成员、字段名、数据取值与引用的元数据保持原文。

## 后果

- 新增界面文案必须同时写三种语言，`pnpm check:i18n` 不通过不能合并。
- 繁体与英文的行业词也在检查范围内，业务中立（ADR 0010）不因翻译失守。
- 后端新增给用户看的提示时，常量消息要在 `.po` 里补译文，拼接消息用 `Msg`；单测会扫描源码里的消息并核对两份目录。
- 用户和模型写下的内容不随界面语言变化；中文团队写的口径名、报告在英文界面里仍是中文，这是有意的。
