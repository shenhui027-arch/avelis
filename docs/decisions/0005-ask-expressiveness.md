# ADR 0005：问数表达能力——多指标、排名、对比与派生指标

- 状态：已采纳
- 日期：2026-10-29

## 背景

M5 之前，问数意图只能表达“单个指标 + 时间范围 + 维度过滤 + 分组”。常见问题如下：

- “各区域销售额前 3”：排名；
- “销售额环比”：对比；
- “销售额和订单数”：多个指标；
- “客单价”：指标之间的比值。

这些都无法回答。

用户问到是否需要另外接一个 text2sql 项目。结论是不需要：Avelis 属于“语义层 / 指标驱动”的 text2sql，模型只给出结构化意图，SQL 由已发布口径确定性编译。正是这一点让后端能识别答案用了哪个口径，并在口径变化后拦截。差距在意图的表达能力，而不在“让模型写 SQL”。

## 决定

1. **意图 v2**（`ask/intent.py`）在原有字段上增加：
   - `metric_codes`：最多 4 个指标，第一个用于排序；
   - `order` 与 `limit`：按第一个指标排名，取前 N（N ≤ 100）；
   - `compare`：`previous_period`（紧邻的上一期，单日即前一天）或 `previous_year`（去年同期，2 月 29 日按 28 日）。

   模型（或演示规则）只填这些字段，后端逐项校验。
2. **执行计划**（`ask/service.py::_fulfil_plan`）：
   - 单指标、无对比时，整条下推为一条 SQL，排序与 `LIMIT` 也在数据库完成。
   - 否则把问题展开为“指标 × 时间段”的子查询。**每个子查询都走完整的单指标治理管线**：两条状态线、完整来源权限、执行前核对、只读执行、缓存规则。
   - 任何一个子查询没有通过，整个答案就按它的原因拦截、拒绝或报错，并说明是哪个指标、哪个时间段。
   - 全部通过后，后端按维度键对齐，计算派生公式与对比列（上一期 / 去年同期、变化、变化率），再排序、取前 N。
   - 多个指标只能用它们共有的维度过滤、分组。
3. **派生指标**是指标的一种类型（`metric_version.kind = derived`）：
   - `expression` 存公式，只允许指标编码、数字、加减乘除、括号、取负。用 Python AST 白名单解析与求值，不执行代码。
   - 除数为 0 或任一组成值缺失时结果为空，不当作 0。
   - **提交时锁定组成指标的具体版本**（`components`）。依赖指纹由“公式 + 锁定版本 + 各组成版本的依赖指纹”计算，所以批准前组成指标换了版本，批准会被拒绝。
   - 问数使用锁定的组成版本，而不是组成指标的最新版本。
   - 组成指标受影响时，派生指标随之受影响，并生成复核任务；组成指标恢复后，派生指标经复核恢复。
   - v0.1 不支持派生嵌套。
4. **数值格式**：结果中的数值以十进制字符串返回，变化率为小数（0.25 表示 +25%），前端负责显示格式。

## 后果

- 组合问题会产生多条 SQL。每条都可以在依据中查看，答案只引用这些 SQL 的结果。
- 排名在多指标、对比或派生时由后端完成。如果某个子查询结果超过行数上限被截断，答案会标明“排名可能不完整”。
- 派生指标不额外引入依赖指纹的计算，复用组成指标已有的治理。
- 演示规则能识别以下说法：“前 N / 最高 / 排名”“后 N / 最低”“环比 / 上一期 / 前一天”“同比 / 去年同期”，以及问题中出现的多个指标名。真实模型通过 `submit_intent` 工具的新字段表达同样的意图。
