# ADR 0014：口径的时间语义、量纲语义与业务日历

- 状态：已采纳（用户要求“第 2-4 批继续优化完成”，2026-11-01）
- 日期：2026-11-01
- 关联：ADR 0009（量纲与引用）、ADR 0010（产品与业务解耦）、过拟合审查报告与第 1 批（PR #26）

## 背景

过拟合审查发现，产品代码默认了演示数据的形态：
- 日汇总；
- DATE 类型的时间列；
- 流量型可加指标；
- 上海时区；
- 金额量级；
- 越大越好。

第 1 批在元数据不够时改为拒绝或标“未知”。这次补上元数据，让其他行业的数据“能用而且算对”。

## 决定

### 1. 口径版本新增时间语义（迁移 0016）

| 字段 | 取值 | 默认 | 含义 |
|---|---|---|---|
| `time_format` | `null` / `yyyymmdd` / `yyyy-mm-dd` / `yyyymm` | `null` | `null` 表示时间列是日期或时间类型；其余表示整数或字符串编码的日期键 |
| `data_grain` | `day` / `week` / `month` / `quarter` / `year` | `day` | 数据本身的最细时间粒度 |
| `time_aggregation` | `sum` / `last` / `avg` | `sum` | 跨时间怎么合：流量型相加；存量型取期末或期间平均 |

规则：
- **时间列类型**：`time_format = null` 时仍要求日期或时间类型。其余格式要求整数或字符串类型，`yyyymm` 要求 `data_grain` 至少为 `month`。
- **编码日期键的过滤**：按格式生成字面量。`yyyymm` 的窗口必须是整月，否则拒绝并说明原因。
- **分组粒度**：`time_grain` 支持 `day / week / month / quarter / year`（周从周一开始）。不能比 `data_grain` 更细；编码日期键只支持 `day` 和 `month`；方言不支持的组合明确拒绝。
- **存量指标（last / avg）**：问数先按 `data_grain` 分桶取数，再在后端合成。`last` 取窗口内有数据的最后一个桶；`avg` 取各成员有数据的桶的平均值。行数超上限时标为截断。日历折算对 `last / avg` 拒绝；跨成员相加仍然允许，因为存量指标在维度上可加。
- **业务时区进入查询**：每次执行只读查询时，连接器把会话时区设为口径版本的 `timezone`。
  - PostgreSQL：`SET TIME ZONE`；
  - MySQL、StarRocks、Doris：`SET time_zone`；
  - Oracle：`ALTER SESSION SET TIME_ZONE`；
  - ClickHouse：`session_timezone` 设置。

  这样字面量边界、按时间分组、TIMESTAMPTZ 列都按业务时区解释。不带时区的时间列含义不变，仍是业务时区的本地时间。SQL Server 没有会话时区：对带偏移的列（`datetimeoffset`）在字面量上写出偏移，不支持按时间分组，并明确说明。
- **预检与覆盖度**：预检的趋势查询按 `data_grain` 取数，覆盖度按 `data_grain` 生成期望期间。
- **新增对比方式 `previous_calendar`**：窗口是整月、整季或整年时，取上一个同类自然期间。原有的 `previous_period`（紧邻的同长度区间）不变。

不做：没有时间列的口径（静态总数）。它牵涉新鲜度、血缘、预检的大量路径，作为已知局限另立。

### 2. 口径版本新增量纲语义（同一迁移）

| 字段 | 取值 | 默认 | 含义 |
|---|---|---|---|
| `value_kind` | `level` / `ratio` / `count` / `null` | `null` | 显式声明量纲；`null` 时沿用表达式推断 |
| `polarity` | `up_good` / `down_good` / `null` | `null` | 期望方向；界面涨跌着色按它，未知用中性色 |

这两个字段都是展示与判断用的元数据，并入 `DISPLAY_FIELDS`，不计入依赖指纹。

### 3. 数据集列契约

受治理与探索数据集、问数结果都返回 `column_roles`：`{列名: {role, label}}`。
- `role`：`dimension` / `time` / `measure` / `change` / `rate`；
- `label`：取口径维度的显示名、指标名，没有时用列名。

前端选图轴、着色、判断变化列，以及 PDF 图表，只读 `column_roles`，不再按值类型或中文后缀猜。报告中原因实体的维度显示名也由后端从口径投影。

### 4. 业务日历（系统设置 `business_calendar`）

存放在 `app_setting` 的 `business_calendar` 键，由管理员维护：

```json
{"weekend_days": [5, 6], "holidays": ["YYYY-MM-DD"], "workdays": ["YYYY-MM-DD"]}
```

- `weekend_days` 用 Python 的 weekday，周一为 0；
- `workdays` 是调休上班日。

日历折算在有日历时：
- 给出两期的节假日数与工作日数；
- 同时给出按工作日的折算（工作日均值、工作日数效应）。

没有配置时，节假日仍为“未知”，只按自然日折算。

### 5. 体验与小项

- 示例问题写出具体日期区间（按今天推算上个自然月）；两个指标没有共有维度时，不生成关系类示例。
- 成员取值按最长匹配：`SKU1` 不会在 `SKU10` 里被选中。
- 证据解释的两个阈值（均匀容差、时间集中度）改为配置项。
- 数字显示体系可配置（`cn`：万、亿；`intl`：K、M、B），后端渲染与前端图表一致。
- 公式常量白名单补充 1e6、1e9、60、24、3600。
- 方言未知时不再回退到 StarRocks，而是跳过依赖方言的判断。
- 前端问数历史按业务时区显示；图表横轴跨年时保留年份；定时任务不预填 cron。

## 后果

- 换行业接入时，治理者在口径上声明时间格式、粒度、跨时间合成方式、量纲与方向，问数与分析据此计算。不声明时沿用默认值，结果与以前一致。
- 已发布口径的默认值与原行为相同，迁移不改变现有结果。
- 已知局限：
  - 没有时间列的口径；
  - SQL Server `datetimeoffset` 列不能按时间分组；
  - 绝对值小于 1e-6 的数用指数形式表示；
  - 中文数量词核验仍是封闭词表。
