# ADR 0009：报告数字按引用渲染、自动归因引擎与评测集

- 状态：已采纳（用户确认先改造再合并 PR #10，2026-10-30）
- 日期：2026-10-30
- 取代：ADR 0007 第 4 点中“从结论文字里提取数字再比对”的全部规则；第 9 点的验收方式

## 背景

ADR 0007 的核验方式是：模型用自然语言自由书写数字，`verify` 再用正则从中文里提取数字，与引用的数据集比对。

PR #10 开发中，这套规则一天内改了 12 次，经过 5 轮 Codex 复核，每轮都还有新反例：

- 放行：“营收千万元”“十分之一”“营收100 万达标”“每 3 个月饼”。
- 误报：“两期总差额”“（万元）”。

中文数字与日期的写法是开放集合。豁免多了会放行，收紧又会误报正常写法。这是方案本身的问题，补规则补不完。

### 开源与业界做法（2026-10-30 调研）

| 项目 | 做法 |
|---|---|
| GROUND（arXiv 2608.26157） | 模型只写 SQL，数字全部来自执行结果；校验对象是 SQL 是否符合口径、粒度、必需过滤、行级权限 |
| InsightPilot（微软，EMNLP 2023） | 模型只编排分析动作；洞察由确定性的洞察引擎计算，明确是为了避免编造 |
| Databricks Genie | 只有完整复用专家核准的参数化查询的回答才标为 Trusted；用基准问题集持续衡量准确率 |
| ThirdEye、wise-pizza | 自动扫描维度、按贡献排序生成下钻；wise-pizza 把两期变化拆成规模与结构两部分 |
| TaskWeaver、Data Interpreter、DB-GPT | 代码优先，在沙箱里执行 Python |

共同点是数字只来自执行结果，没有一家先让模型写数字、再事后核对。

## 决定

### 1. 报告中的数字一律用占位引用，由后端渲染

模型提交报告时不写数字，而是写占位；后端按数据集取值、格式化后生成正文。

**占位语法**（花括号内；写 `{{`、`}}` 输出字面花括号）：

| 写法 | 含义 |
|---|---|
| `{D5.成交额}` | 数据集只有一行时取该列；多行时报错 |
| `{D5.成交额[区域=华东]}` | 按条件选行，多个条件用逗号分隔；必须恰好选中一行（求和请先用 `derive`） |
| `{D3.门店[#1]}` | 第 1 行（按数据集顺序）；用于带数字的名称，如“广州10号店” |
| `{D12.value}` | 计算类数据集的汇总值（summary.value） |
| `{D5.rows}` / `{D5.distinct(门店)}` | 行数、不同值个数；截断的数据集不可用 |
| `{window.current}` / `{window.compare}` | 本期、对比期；默认按日期区间显示，`|month` 显示为“2026 年 9 月” |

**格式**（可叠加，从左到右生效，四舍五入 ROUND_HALF_UP）：

| 后缀 | 效果 |
|---|---|
| 无 | 原值去掉多余的零 |
| `|d2` | 保留 2 位小数 |
| `|int` | 取整 |
| `|pct1` | ×100，保留 1 位，带 % |
| `|pp1` | ×100，保留 1 位，带“个百分点” |
| `|wan1` / `|yi2` | 除以 1 万 / 1 亿，带“万”“亿” |
| `|abs` | 取绝对值 |

**渲染结果**：
- 每条结论保存 `template`（模型原文）、`text`（渲染后的正文）、`segments`。
- `segments` 是文字段与数值段的序列。数值段记录：数据集编号、取值路径、格式、原值、显示值。
- 前端按数值段渲染，悬停可查看来源数据集和原值。导出的 PDF、Markdown 使用 `text`；CSV 另附一张占位来源表。
- **引用由占位自动得出**：结论的 refs 等于显式 refs 与所有占位涉及的数据集的并集。这样就不会再出现“数字在 D12、却只引用了 D18”的情况。

### 2. 核验改为结构检查

不再从正文里提取数字。下列规则适用于事实、计算类结论的 `template`，以及标题、摘要、“未解释”字段：

1. **占位必须能解析**：每个占位都要解析成功（数据集存在、列存在、恰好选中一行、格式合法）。否则这条结论或字段判为未核实，并写明原因。
2. **占位之外不能有阿拉伯数字**：半角、全角都算，日期也不例外，日期请用 `window` 占位或数据集里的日期单元格。
3. **占位之外不能有中文数字字符**：沿用现有的残留检查（零〇一二两三四五六七八九十百千万亿），但白名单冻结为当前的非数量词与“两期 / 两者”规则：
   - 白名单里的词不算数字，但白名单不再为了让模型通过而扩充；
   - 模型的写法被误判时，通过修订提示让它改写；
   - 确需修改白名单时，同步修改本 ADR。
4. **方向与符号一致**：用了 `|abs` 的数值段，前方 8 个字以内若出现增长类词（增长、上升、提高、增加）而原值小于 0，或出现减少类词（下降、减少、降低、下滑）而原值大于 0，判未核实（“方向与数值符号不一致”）。
5. **必须有引用**：事实、计算类结论至少引用一个数据集，显式引用或通过占位引用均可。

推断、建议类结论，以及 premise、validation 字段：占位照常渲染；占位之外允许出现数字（这是假设或方案，不是事实），界面标为“推断 / 建议，未核实”。

修订仍然只给一轮。反馈逐条写明问题：哪个占位解析失败、占位外出现了哪个数字、哪里方向不一致。`found_in` 机制删除。

ADR 0007 第 4 点中以下内容全部删除：日期、日历词、名称、对比用语的豁免，数字提取与按精度匹配，“下降”后可对应负值。截断标记、需要全集的计算拒绝截断输入、因子拆解的舍入阈值等规则保持不变。

### 3. 自动归因工具 `explain_change`

**参数**：
- 指标；
- 本期与对比期，默认取运行窗口；
- 候选维度，可选，默认取该指标允许、且当前用户可见的维度，最多 8 个；
- 深度 1 或 2；
- `top_k`。

**执行**：
- 每个维度发一次受治理查询，复用 `fulfil`，每次都计入查询预算。
- 深度为 2 时，只对第一层解释力最高的 3 个维度两两组合。
- 某个维度的查询结果被截断时，标为“未完全扫描”，不参与排名。

**计算**（参照 Adtributor，确定性实现）：
- 每个成员的贡献占比 EP = 该成员差额 / 总差额；
- 每个维度的惊异度：两期成员分布之间的 JS 散度；
- 维度按惊异度排序；维度内的成员按 EP 降序，取到累计 EP ≥ 0.67 为止；
- 比率类指标（派生公式为 a / b，例如客单价）拆成结构效应与比率效应：
  - 结构效应：Σ (w₁ − w₀) · r₀
  - 比率效应：Σ w₁ · (r₁ − r₀)
  - 两者相加等于总差额，舍入差单列。

**输出**：一个数据集，列为维度、成员、对比期值、本期值、差额、EP、惊异度、结构效应、比率效应。summary 写明首要维度与累计解释比例。

**为什么不引入 wise-pizza**：它依赖 lasso 求解和 pandas，我们的数据集规模小。Adtributor 加结构 / 比率拆解大约 200 行代码，确定性强，容易测试。多维组合搜索以后有需要再评估。

### 4. 评测集代替“单次运行必须全部核实”

**评测集**：`backend/tests/eval/analysis_questions.yaml`，不少于 20 题，来自 `ec-truth.json` 中预埋的场景，并覆盖以下四类：

| 类型 | 预期 |
|---|---|
| 维度原因（门店关闭、区域投放削减） | 结论指出该成员 |
| 因子原因（促销导致客单价下降） | 结论指出该因子 |
| 治理原因（口径变更、采集延迟） | 结论引用 `changes` 或 `data_health` |
| 反例（两期没有明显变化） | 不编造原因，如实写“未解释” |

**判分（确定性）**：在事实、计算类结论引用的数据集里，预期的成员、因子或事件出现在前 k 行，且结论正文提到它，记为命中。评分代码不调用模型。

**运行器**：`scripts/eval_analysis.py --repeat 2`，结果写到 `.demo/eval/<时间>.json`，并生成 Markdown 汇总。每题记录：是否命中、未核实数、是否完成、工具调用次数、用时、token 数。

**合并门禁**（PR #10 及以后修改分析智能体的 PR）：

| 指标 | 门槛 |
|---|---|
| 完成率 | ≥ 95% |
| 事实与计算类字段的未核实数 | 0（按设计应为 0，出现即排查） |
| 首要原因命中率 | ≥ 80% |

门槛可以调整，调整时修改本 ADR。

**测试分层**：
- **确定性回放**：录制一次成功的真实运行（模型消息，不含密钥），用假模型回放。在回放上严格断言占位解析、渲染、核验、修订、图流程和预算。
- **真实模型验收**：保留 07 和 08，断言运行成功、命中首要原因、未核实数为 0。只有传输层错误（连接失败、SSL、超时）时测试重跑一次；内容问题不重跑。
- 稳定性以评测集的结果为准，不再依赖单次运行。

**成本**：每轮评测约 40 次分析运行。使用的是已授权用于验收的 DeepSeek 密钥。

## 实施顺序

都在 `m8-analysis-agent` 分支上完成，全部做完再审查、合并。

1. 占位语法、渲染、核验重写；前端数值段与导出；系统提示与修订提示；删除旧的提取代码与测试。
2. `explain_change` 及单元测试，加入第 5 点的标准流程（第 2 步优先用它）。
3. 评测集、运行器、回放测试；验收用例按上面的分层调整。
4. 全量验收与评测达标，再经 Codex 复核与最终审查，然后合并。

## 后果

- 正文里的数字由构造保证可追溯，核验代码从约 300 行正则减少到结构检查；Codex 和测试不再需要穷举中文写法。
- 模型的写作自由度下降：数字必须写成占位。DeepSeek 等模型需要通过系统提示和示例学会这种写法，评测集用来衡量效果。
- 旧的 `analysis_run`（没有 `template` 字段）只存在于开发库中，不做兼容，开发库直接重建。
- 归因由引擎先给出排名，模型负责解读和下钻，第 5 点标准流程的第 2 步不再依赖模型逐个挑选维度。
