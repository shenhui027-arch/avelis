# ADR 0010：产品代码与具体业务解耦

- 状态：已采纳（用户要求，2026-10-30）
- 日期：2026-10-30

## 背景

Avelis 是**通用的数据治理基座加智能问数**产品，面向任何行业的数据库与口径。开发与验证用的是合成电商数据集（ADR 0007 第 10 点），但电商只是演示和评测场景，不是产品的一部分。

2026-10-30 检查 `m8-analysis-agent` 分支，产品代码里没有依赖电商表名、列名的逻辑，耦合集中在“示例”这一层：

- 给模型的系统提示与工具说明里的例子全是电商写法（成交额、门店、华东、客单价，甚至写了演示库的表名 `ec_dw.dws_store_daily`），会把非电商客户的模型往错误方向引导；
- 前端问数页、分析页的示例问题写死为电商问题；
- 错误提示、API 说明、代码注释里的示例用了演示口径编码（如 `paid_sales / orders_cnt`）。

## 决定

1. **产品代码不出现具体业务。** `backend/src`、`frontend/src` 中的逻辑、提示词、工具说明、错误提示、界面文案、注释，都不写某个行业的指标、维度、表名或取值。
   - 需要举例时，有两种做法：
     - 用中性占位，例如 `<指标>`、`<维度>`、`<成员>`、`metric_a / metric_b`；
     - 用跨行业通用的说法，例如“总量 = 数量 × 单价”“按地区、渠道等维度”。
   - 通用的数据与统计术语不受限制，例如维度、成员、差额、占比、类目轴。
2. **给模型的示例从用户自己的元数据生成。**
   - 系统提示中的片段写法、取值示例，每次运行时从当前用户可见的已发布口径中，确定性地挑一个指标及其维度来填写：按编码排序取第一个有维度的指标。
   - 没有可用口径时，退回到中性占位。
   - 这和 WrenAI、SuperSonic 从用户自己的语义层召回示例的做法一致。
3. **示例问题由数据决定，不写死在前端。**
   - 业务域新增可选的 `example_questions`（文本列表），由业务域管理员维护。
   - 后端接口返回当前用户可见业务域的示例问题。没有配置时，用模板从可见口径生成，例如“<指标> 按 <维度> 的最近一期排名”。
   - 问数页、分析页从接口读取示例问题。
4. **演示与评测内容只放在演示与测试里。**
   - 电商数据集、演示口径、示例问题的种子，只放在 `scripts/`（如 `ec_data.py`）、`backend/src/avelis/demo_setup.py`（只由 `bootstrap demo` 调用）、`backend/tests/`、`docs/` 与评测集里。
   - 产品代码不得 import 演示模块。
5. **检查方式。** 增加一条单元测试，扫描 `backend/src` 与 `frontend/src`（排除 `demo_setup.py` 和自动生成的 `openapi.json`、`schema.d.ts`），只要出现演示数据集特有的词（ec_ 库名、演示表名、演示口径编码，以及成交额、门店、客单价、华东等演示用的业务词），测试就失败。
   - 词表放在测试里，随演示数据集一起维护；
   - 新增演示场景时同步补充词表。

## 实施

在 PR #10（`m8-analysis-agent`）上完成，作为 ADR 0009 第 2 步之后的一个独立提交，在第 3 步之前完成：

- 改写 `analysis/agent.py`、`analysis/tools.py`、`analysis/grounding.py`、`analysis/calc.py`、`ask/agent.py`、`ask/intent.py`、`governance/derived.py`、`api/governance.py` 中的示例；
- 实现按元数据生成提示示例；
- 业务域的 `example_questions` 字段（并入未合并的迁移 0009）、接口，以及前端读取；
- `demo_setup` 为演示业务域写入示例问题；
- 加上第 5 点的扫描测试。

## 后果

- 换一个行业的数据库接入时，模型看到的示例和界面上的示例问题都来自客户自己的口径，不会出现电商词汇。
- 提示词示例随用户元数据变化，回放测试需要固定数据夹具，ADR 0009 第 5 点已有这项要求。
- 以后若要证明通用性，可以再加一个非电商的小型合成数据集进入评测集。这次不做。
