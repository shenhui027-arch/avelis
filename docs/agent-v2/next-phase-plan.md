## 2. 实施顺序（相对 ADR 0013 草稿的调整）

ADR 0013 的第一版是：假设检查点 → 结论续问 → 个人经验 → 前端 → 测试；理解阶段的暂停放在第二阶段。
**按 E2 的证据，建议把“理解检查点的回答与恢复”提前到第一版的第一步**：

1. **理解检查点：回答后恢复**。现在运行停在待澄清之后就结束了，这也是 PR #11 审查第 3 条记录的已知局限。
   - 改为用户回答追问之后，在原运行上继续；
   - 预算接着计数（已有 `Budget.restore`），恢复时防止重复恢复，并重新检查权限；
   - 定时任务里遇到追问，照现在的做法暂停任务。
   - 理由：E2 里 27% 的运行停在这里，这一步不做，后面的检查点都没有机会起作用。
2. **假设检查点**（ADR 0013 第 1 点）：预检之后列出相关表、准备用的关联和待检验的假设，每一项写明来源（上游元数据、经验、血缘，还是 R 的线索）。
   - R 的参考表作为“模型提议”的来源保留：对有共享键的表召回好（投放表 8/8），对没有共享键的召回为 0（营销活动 0/12），所以必须让用户确认或补充。
   - “自动”模式下，只有提议里包含没有依据的线索时才停下来问。
3. **个人经验闭环**（ADR 0013 第 2 点）：确认和纠正整理成可编辑的候选，用户明确保存后才入库，下次召回。
   - 第一版类型：表关联、驱动因素、取值别名（例如 douyin = 抖音，E1 里大量出现）、口径约定。“均价按件单价”这一类，正好对应 E2 里的追问。
4. **结论续问**（ADR 0013 第 1 点）：对已完成的报告质疑或补充规则，以续问运行实现。
5. **评测：交互模拟**（ADR 0013“评测”一节）。不做这一项，前四项的价值都衡量不出来。
   - 先写业务知识卡：由不看预埋答案的会话编写，不能包含答案；
   - 再跑小规模的交互模拟。需要另行授权模型费用。
   - 迁移与污染评测放在第二阶段。

**第二阶段**（保持 ADR 0013 草稿的内容）：
- 经验压缩；
- 团队与全局作用域，提升需要审批；
- `pg_trgm` 检索；
- “关联 / 驱动因素”类经验转为确定性检验。E2 中“查到了却解释不对”的问题，要靠这一项解决；
- 同一次运行里修订结论；
- 迁移与污染评测；
- 上游元数据导入。

## 4. 思考强度对照（原第 3 项；用户 2026-10-31：“模型就不换了，你可以用更强的思考来做”）

- **目的**：区分问题出在模型能力还是系统设计。模型不变（DeepSeek Flash），只把分析阶段的思考强度调到“最高”。不用“高”档：ADR 0012 实测“高”和“低”的推理 token 相近，只有“最高”明显更多。
- **时机**：E2 分析完成之后进行，不改 E2 的冻结计划。
- **条件**：只改思考强度，取 max；其余与 E2 相同（16 个场景，每个 2 次，冻结的种子，评分器 v2.1.3，私有库 avelis_e1）。
  - 先跑 B0 @ max（32 次）；
  - 预算够的话，再跑 E2 里通过最多的组合 RH @ max（32 次）。RH 和 B0 的差在噪声范围内，选它只是按预先定的“效果最好”规则。
  - 运行前先估算费用；额度不够就只跑 B0 @ max。
- **预算上限**：模型请求数、工具调用数、查询数、时长、输入 token 的上限都不变。只把累计输出 token 上限按“最高”档的实测比例调高，在运行前算好、写进 manifest 冻结：
  - ADR 0012 实测推理 token：低 3,942–7,946，最高 9,149–12,128，按两档区间中点算比例约为 1.79；
  - 输出上限 30,716 × 1.79 ≈ 54,976。
- **费用**：从 E2 授权的 20 元里剩下的部分出（剩余约 13.26 元），E2 和这次对照合计不超过 20 元，用 `--spent` 带上已经花掉的金额。
  - 按 E2 的 B0 每次约 0.048 元、输出费用随推理 token 增加估算，B0 @ max 约 2–3 元，RH @ max 约 3–4 元，两组都在额度内。
- **对照基准**：拿 E2 里同一条件“低”档的结果对比。
  - 判读：“最高”档如果明显提高首要原因命中，说明模型能力是主要限制；如果没有提高，说明问题主要在系统设计（发现与检查点）。
  - 回报时附上每次通过的平均成本和耗时中位数。
- **授权**：用户是在协调会话里说的这句话。本会话的权限检查如果不放行，就停下回报，不绕过。
- **结果（2026-10-31，详见 results-e2b.md）**：
  - 第一版因 60 秒超时作废。放宽超时与运行时长后，E2b-2 只跑了 B0 @ max，RH @ max 没有跑。
  - 结果：
    - 通过 12 / 32，和“低”档相同；首要原因命中 11，“低”档 10；
    - 完成运行的耗时中位 278 秒，“低”档 77 秒；
    - 每次通过 0.416 元，“低”档 0.127 元。
  - 判读：首要原因命中没有明显提高，问题主要在系统设计。“最高”档不用于产品。
