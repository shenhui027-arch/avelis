# Avelis v0.1 验收说明（汇总）

本文汇总全部验收：怎么运行、每个故事和异常场景做了什么、预期是什么、实际结果。各里程碑的细节见 [M1](acceptance-m1.md)、[M2](acceptance-m2.md)、[M3](acceptance-m3.md)（浏览器走查截图）、[M4](acceptance-m4.md)、[M5](acceptance-m5.md)。

## 运行

```bash
uv run scripts/acceptance.py --fresh
```

- 一条命令从零开始：删除演示容器与数据卷 → 重建 → 灌数 → 核对基线 → 迁移 → 单元测试 → 验收 → 前端构建 → 演示环境回到故事 1 起点。
- 报告写入 `.demo/acceptance-report.md`。
- 加 `--no-llm` 跳过 2 项真实模型用例（不向模型服务发送数据）。
- 所有用例都在真实的 StarRocks 3.5.14、MySQL 8.4、PostgreSQL 18、Valkey 8 上执行，经 HTTP API 以不同角色的真实账号操作。
- 断言检查实际执行行为：是否执行了 SQL、返回值、数据库中的状态、事件与审计，不只看状态码。

## 验收故事

| 故事 | 用例 | 做了什么 | 预期（断言的实际行为） |
|---|---|---|---|
| 1 采集与可追溯的列级依赖 | `test_m1::test_01` | 采集 StarRocks 与 MySQL | 观察到 12 个 StarRocks 资产。`sales_amount` 的值来自 `paid_amount`（聚合），`region` 是分组键。粒度：主键表直接观察；视图由 GROUP BY 推出。外部表自动接到 MySQL 真实表。重复采集不产生新版本 |
| 2 发布“实付销售额” | `test_m1::test_02` | 负责人创建并提交，复核者批准 | 负责人不能自审（403）；版本绑定依赖指纹 |
| 3 问数得到 300 | `test_m1::test_03` | 分析师提问“2026-09-15 华东区实付销售额” | 真实执行得到 **300.00**；答案带 SQL、口径版本与来源证据；再问命中缓存；无业务域的用户检索不到，不执行 |
| 4–5 定义改为净额，拦截旧口径 | `test_m1::test_04_05` | root 把视图改为 `SUM(paid - refund)` 后采集 | 事件 `definition_changed`、`derivation_changed`；指标进入 `affected`，生成复核任务。再问被拦截：**不执行 SQL，不返回 270**。历史答案保留 300，并标记需重新确认 |
| 6 甲：恢复原定义 | `test_m1::test_06a` | 改回原定义，负责人复核 | 定义恢复前不能按“已恢复”结案；观察恢复但未复核时仍拦截；复核后再问得到 **300.00** |
| 6 乙：发布新口径 | `test_m1::test_06b` | 再次改为净额；发布“退款后净销售额”承接 | 新口径得到 **270.00**；原口径失效，问它时提示改用新口径；历史答案仍指向原版本 300 |
| 7 删除被依赖的列 | `test_m4::test_07` | `DROP COLUMN paid_amount` | **采集前**：执行前核对发现依赖列已删除，新问题和之前缓存过的问题都被拦截（`metadata_stale`），只排队一次采集；订单数不依赖这一列，照常回答；关闭核对时数据库如实报 1064。**采集后**：受影响口径被拦截；订单数、类目销售额（270.00）照常回答 |
| 8 导入血缘 | `test_m2::test_01`–`test_06` | 导入 SQL 文件、Python 代码、Shell 脚本 | 解析边带行号证据；模型候选确认前不进入已确认血缘；驳回、接受、修改后状态正确；动态 SQL 补参数后可解析；重复导入幂等 |
| 9 粒度与放大 | `test_m1::test_09` | 订单经 1:N 关联明细后求和 | StarRocks 实际给出 400；系统**阻止发布**并说明原因。改为先聚合再关联后得到 **300.00**。跨域类目销售得到 **270.00**；只属于交易域的用户被拒绝执行 |

问数智能体（`test_m1::test_11`–`test_14`）：

- 多轮追问在服务重启后能续接（270.00）；
- 有歧义时给出候选；
- 工具调用循环使用脚本化模型；
- 真实 DeepSeek 端到端：先问得到 270.00，追问“那华北呢？”得到 150.00；默认不把查询结果发给模型；已失效的口径不会被执行。

## 异常场景（M4）

| 场景 | 用例 | 预期（断言的实际行为） |
|---|---|---|
| 越权：检索、血缘图、结果、缓存 | `test_m4::test_01` | 无权的资产 404，也不出现在列表和血缘图中；无权用户问同一问题被拒绝，拿不到别人的缓存结果，也读不到别人的答案 |
| 伪造意图、注入取值 | `test_m4::test_02` | 不可见的指标、无权的来源、未开放的维度都被拒绝，不生成 SQL；注入的取值只成为转义后的常量，结果为 0，表未被破坏 |
| 提示注入 | `test_m4::test_03` | 问题夹带 DROP 时，执行的仍是确定性 SELECT；恶意表注释作为数据保存，不改变任何状态 |
| 元数据过期：定义改了但未采集 | `test_m4::test_06b` | 视图改为净额但未采集：同一问题不返回缓存的 300，也不按新定义返回 270，而是拦截并排队采集；改回原定义后缓存重新可用（300.00） |
| 不支持的 SQL | `test_m4::test_04` | UNION 视图标为 `unsupported`，指纹“证据不全”；基于它的指标不能提交 |
| 查询超时 | `test_m4::test_05` | StarRocks 真实返回 5024，答案 `db_timeout`，不缓存 |
| 同名对象 | `test_m4::test_06` | 改名保留资产；删后重建是新资产，人工声明不继承；跨库同名不混淆，导入缺库名时不猜测 |
| 外部表来源变化 | `test_m4::test_08` | MySQL 删列使身份映射变为 `mismatch`，下游视图受影响；MySQL 改类型经 Catalog 表传到类目销售额，口径被拦截 |
| worker 进程 | `test_m4::test_09` | Redis 唤醒的任务、只在 job 表中的任务都完成；执行中退出的任务记为失败 |
| 会话存储丢失 | `test_m4::test_10` | 删除 `avelis_agent` 后问数正常，模式自动重建 |
| 未归属业务域的资产 | `test_m4::test_11` | 默认分析师不可见、不能查询；改为 `allow` 后可查（5.00） |
